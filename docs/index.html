Domain modeling and C4 architecture diagrams from code

c4-diagram is an open-source Agent Skill that turns a codebase into a shared domain glossary and a set of C4 model diagrams. It agrees the words for your domain with you in GLOSSARY.md, reads the code into an editable c4-model.json with a file:line source for every fact, and renders System Context, Container and Deployment diagrams. Scripts check every diagram against the C4 rules and the glossary.

Install

/plugin install c4-diagram --marketplace STBlackHawk/c4-diagram-skill

Or npx skills add STBlackHawk/c4-diagram-skill, or clone it into ~/.claude/skills/c4-diagram. Then ask: “Draw a C4 diagram of this repo.”

How it works

  1. Agree the domain language. The agent lists candidate terms from your code, interviews you in short rounds, and writes each settled term to GLOSSARY.md with its rejected synonyms.
  2. Discover. It reads deploy specs, CI, config, routes, clients and schemas, and names every element with a glossary term.
  3. Draw and check. It renders HTML, SVG and PNG, light and dark, and runs the C4, domain, geometry and accessibility checks.

FAQ

How do I generate a C4 diagram from my code?
Install the skill, open Claude Code in your repo and ask for a C4 diagram. The agent agrees a glossary with you, writes c4-model.json from the code, and renders the System Context, Container and Deployment diagrams.
What is a ubiquitous language, and why does a diagram need one?
In Domain-Driven Design, the ubiquitous language is the one set of words that the team, the code and the docs use for the domain. The checker fails any diagram that uses a rejected synonym, so every reader sees the same system.
How is it different from Structurizr, PlantUML C4 or Mermaid C4?
Those tools render a model that you write by hand. c4-diagram writes the model from the code, with a source for each fact, and checks it before it renders.
